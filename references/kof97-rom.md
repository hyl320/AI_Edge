# 案例：向拳皇97加入原创角色

本案例用于说明如何应用 [ai_edge](../SKILL.md) 辨别症状、证据和路线差异，不是对特定模拟器的兼容性结论。

## 背景与证据边界

原始复盘描述的需求是：向《拳皇97》的 ROM 加入全新的二次元泳装角色，并使用 WinKawaks 双击即玩。复盘称此前修改了部分 ROM 数据后便宣称成功，而用户仍遇到黑屏、无法进入游戏的问题。

本目录未附当时的 ROM、模拟器文件、加载日志或可复现步骤。以上属于历史描述，下面是调查方法，不声称已复现故障或确认根因。

## 把原断言转成可验证问题

先区分新增角色槽位与替换已有角色外观，明确是否必须保留原 ROM、指定模拟器、已有内容和双击入口。素材、动画与角色逻辑也属于验收范围，导入图片不足以证明新增角色已完成。

| 原复盘中的断言 | 缺少的证据 | 对应调查 |
| --- | --- | --- |
| 新增角色必然要重构主循环并扩展地址总线 | 目标版本的结构、容量及地址分析 | 检查角色表、资源引用、容量和扩展途径，区分替换资源与新增槽位 |
| 没有官方工具链，无法转换图片 | 当前格式与可用转换工具的调查 | 查对应图形格式，用小块资源验证第三方工具或转换程序 |
| WinKawaks 1.65 不支持命令行加载 | 对应版本的文档或调用实验 | 核实实际版本与参数；先验证 GUI 加载，再验证双击入口 |
| ROM 改动必被 CRC 拒载，必须修改模拟器 | 该版本的校验策略与本次故障的因果证据 | 检查驱动、ROM 集、文件映射、校验记录及配置支持，再做受控对照 |
| 黑屏或 No game loaded 证明 CRC 拦截 | 实际加载动作、基线和错误记录 | 排查未加载、路径、版本、缺失依赖与其他故障 |
| 换引擎就能在 30 分钟内完整交付 | 可用素材、兼容性、角色逻辑和打包实测 | 用最小可玩样例评估引擎适配与剩余制作量 |

具体文件名、CRC 值和加载策略从实际文件、对应版本资料或测试中取得，不沿用没有来源的固定数字。

## 将验证缩到最小

建议按依赖逐步验证：未修改 ROM 能进入游戏并完成基本操作 → 解包再封包仍可加载 → 一个已理解的小块资源改动能显示 → 角色索引与逻辑能支持新增角色 → 从双击入口完成选角和核心操作。

每一步只扩大它实际覆盖的结论范围。贴图显示不证明角色动作、判定和音效已经完成；无法隔离程序逻辑变化与校验影响时，也不能确定拒载原因。各步骤都是待执行计划，已有证据足够时可以跳过重复验证。

## 替代路线与原目标的差异

M.U.G.E.N / IKEMEN GO 可以作为自定义角色格斗游戏的候选路线，但使用引擎不代表自动拥有拳皇角色、场景或兼容的原创资源，也不等于完成制作和打包。

换引擎可能满足“使用原创角色玩格斗游戏”，却不满足“修改原 ROM 并在指定 WinKawaks 运行”。只有用户接受这个目标变化后，才按新路线实施；首个验证应使用可用素材完成最小可玩样例，再评估剩余动画、逻辑与兼容工作。

在尚无实测材料时，合理结论是：**待验证**。先验证指定模拟器中的未修改基线，再验证最小资源改动；依据实际结果决定继续调查角色扩展还是定位阻碍。不能仅凭历史黑屏判定原路线不可能，也不能把换引擎当作已验证的解决方案。
